Karar noktası: asenkron DWA gerekli miydi?

Hayır — reddedildi. GIL gerçeği: saf Python dwa.plan() worker thread'de de GIL'i tutar, tick yine bloklanır. Mimari-tasarim agent'ı bu yönde net karar verdi; kodlama + code-reviewer onayladı. Gerçek çözüm maliyeti düşürmekti:

  • Swept-cell cache (dwa.py): build_swept_cells sonucu (vx, yaw, n_cells) → hücre listesi, OrderedDict FIFO (512). Aynı adaylar her tick'te aynı geometriyi ürettiğinden isabet oranı 1.0.
  • Döngü birleştirme (score_candidate): çarpışma + maliyet + unknown 3 ayrı sweep → tek geçiş (early-exit korundu).
  • Costmap yayın bölücü (autonomy_node.py:920): % 3 → % 4 (to_json ~11ms artık 2.5Hz).

Kritik bulgu: avoid terimi ölü kod

Dead code — envanter #13

score_candidate'de avoid döngüsü collides ile aynı eşiği (inflated ≥ COST_YELLOW) tarıyor. Çarpışan aday −inf alıp eleniyor; çarpışmayan adayda hiçbir hücre eşiği aşmıyor → avoid = 0 her zaman (planlama agent'ı 476 aday-değerlendirmede kanıtladı). Sonuç: dwa_w_avoid 2.0→1.0 değişikliği davranışsal olarak nötr — P2 180° dönüşün gerçek çözümü yalnızca 4-kadran atan2'dir. Gerçek "smooth kaçınma" istenirse ayrı bir mesafe ölçüsü gerekecek.

02

P2 sarı duba 180° dönüş

Kök neden: eski max(goal[0], 0.001) bearing'i 0'a değil 90°'ye çekiyordu — atan2(lat, 0.001) hedefin lateral'ine göre ±90° üretir. Hedef arkada kalan araç bu yüzden dönüş adayını hiç kazanamıyordu.

Çözüm: tam 4-kadran atan2(goal[1], goal[0]) (dwa.py:331).

Ölçüm (goal = (−5, 0.1))Değer
Bearing — yeni formül178.85° (≈π, doğru)
Bearing — eski formül89.43° (hata)
yaw=0 adayı heading — yeni0.006 (düşük, dönmeli)
yaw=0 adayı heading — eski0.503 (yanlış yüksek)

Doğrulama: tam plan() çağrısında hedef arkadayken dönüş adayı (|yaw| ≥ 20°/s) seçiliyor; 2 regresyon testi eklendi (test_p2_180_goal_behind_four_quadrant_bearing, test_p2_plan_turns_when_goal_behind).
